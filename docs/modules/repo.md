# 设置存储（repo）与平台能力（platform）

两个小包，它们做的事是「碰系统」：一个是设置落盘，一个是注册表与资源管理器。

## 定位

`repo` 是界面设置的持久层。`platform` 是系统调用的收口。

它们存在的理由是**边界**：读写注册表、调资源管理器、决定数据目录放哪，
这些都不该散落在业务代码里。业务层碰到系统调用时只有一个去处。

## repo：一个 JSON 文件

### 为什么不是数据库

这里存的全是「删了不丢任何对话」的东西：主题、语言、字号、上次工作目录、
当前引擎、各引擎的可执行文件路径。二三十个键、没有查询、没有关联、没有并发写者。

为此背一个 SQLite（CGO 或纯 Go 移植几百 KB）不划算。一个 JSON 文件足够，
而且用户出问题时能直接打开看、改、备份——那是数据库做不到的。

### 存储模型

```
内存 map[string]string  ←→  一个 JSON 文件
```

- **读走内存**：设置项在启动时一次性载入，之后只读
- **写走「改内存 → 立刻落盘」**
- **落盘用临时文件 + Rename**：直接覆盖时断电会留下半个 JSON，
  那份文件坏了，应用下次就起不来
- **键排序后序列化**：让文件对人可读、对 diff 友好，也让「同一次改动」
  在两次运行间产生稳定字节，出问题时能直接比对
- **空值等于删除**：否则文件里会堆一串 `"key": ""`，界面上还得再判断一次空

### 坏文件怎么办

**改名留档 + 用空设置继续**。设置坏了不该让应用起不来——
用户至少还能打开界面去改回来。留档文件是 `settings.json.broken`，
原因写进日志。

### 它不存什么

会话、用量、模型配置、技能开关都不在这里。那些是引擎的账本，
我们只在需要时读写它们的文件，不复制一份。数据归属见
[DATA-MODEL.md](../DATA-MODEL.md)。

## platform：三类系统能力

| 能力 | 真值在哪 | 为什么不能只在设置文件里 |
|---|---|---|
| 开机自启 | `HKCU\...\Run` 注册表值 | 用户可在任务管理器里禁掉；只读设置文件会显示「开」而实际不生效 |
| 恢复上次会话 | 设置键 + 引擎的会话文件 | 记的是路径，内容永远在引擎那边；文件被删了就安全地落在空会话 |
| 数据目录 | `%LOCALAPPDATA%\OhMyPiDesktop` | 用户报「设置不对」时最快的排障路径是直接看到那个 JSON 文件 |

开机自启写入的值带 `--hidden`：登录后只拉起托盘，不往屏幕上弹一个空窗口。

**注册表读写在 HKCU 下**，不需要管理员权限，也不需要 UAC 弹窗。
这是「桌面应用不写系统级配置」这条纪律的具体落点。

### 它不被谁依赖

`platform` 只被 `desktop` 与 `service` 使用。它不进 `engine`、`repo`、`domain`
——那些层不碰系统调用，测试它们也不需要 Windows。

平台特定代码按 `//go:build windows` 分文件，不写 `runtime.GOOS` 大分支。
本项目只面向 Windows，非 Windows 版本只要求能编译通过（托盘与开机自启会退化成空实现），
不保证行为一致。

## 不变量

| 不变量 | 原因 |
|---|---|
| 设置坏不能让应用起不来 | 用户至少还能打开界面去改回来 |
| 落盘走临时文件 + Rename | 直接覆盖时断电会留下半个 JSON，下次启动就起不来 |
| 空值等于删除 | 否则文件里堆一串空值，界面上还得再判断一次 |
| 开机自启的真值在注册表 | 用户能在任务管理器里禁掉它，设置文件里的值会骗人 |
| 平台代码按 build tag 分文件 | 不写 `runtime.GOOS` 大分支，非 Windows 编译能过就行 |

## 取舍

| 取舍 | 代价 | 收益 |
|---|---|---|
| 一个 JSON 文件而非数据库 | 没有查询与关联 | 二三十个键用不上那些；用户能直接打开改 |
| 内存读 + 落盘写 | 写要同步落盘 | 读不碰磁盘，首屏不等人 |
| 注册表只写 HKCU | 不能写系统级启动项 | 不需要管理员权限，不弹 UAC |
