# 页面结构

十一个路由。每个页面回答一个真问题。

| 路由 | 页面 | 回答的问题 | 引擎差异 |
|---|---|---|---|
| `/overview` | 概览 | 两个引擎什么状态、最近花了多少、有什么能接着聊 | 每个引擎一张健康卡 |

**概览页的数字在就绪前不显示。** `ready` 为假时六个读数都显示为 `—`：
「0 个会话」是一个断言，而那一刻只是还没数完。页头下方挂一条「正在核对…」+ 「重新检测」。
| `/chat` | 对话 | 它在干什么，我下一步说什么 | 子代理面板仅 omp |
| `/mcp` | MCP | 有哪些 MCP 服务器，连上没有 | 启停写的键不同，由后端消化 |
| `/workspace` | 工作区 | 它到底改了什么，我能不能收成一次提交 | 无 |
| `/sessions` | 会话 | 我以前聊过什么，哪些能接着聊 | 列表按当前引擎过滤 |
| `/models` | 模型 | 现在能用哪些模型，密钥配了没 | 登录向导仅 omp |
| `/skills` | 技能 | 我有哪些技能，哪些开着 | 发现规则不同，UI 同构 |
| `/plugins` | 插件 | 我装了哪些扩展 | 读各自的登记清单，装卸走各自 CLI |
| `/usage` | 用量 | 花了多少 token，花在哪 | pi 只有会话内用量 |
| `/apps` | 应用 | 两个引擎装没装、要不要更新 | 分发渠道与命令各不相同 |
| `/settings` | 设置 | 外观、引擎路径、工作目录、关于 | 引擎路径按引擎分开 |

## 状态归属

| 状态 | 住哪 | 理由 |
|---|---|---|
| 当前轮（流式块） | `stores/chat.turn` | 高频变化，只在这一处 |
| 历史轮 | `stores/chat.history` | 由后端投影，前端不再算 |
| 引擎选择（omp/pi） | `stores/app.engineKind` + 后端设置 | 输入框与多个页面共用 |
| 子代理 roster | `stores/agents.roster` | 仅 omp；随会话切换清空 |
| 会话列表 | `stores/app.sessions` | 跨页共用 |
| 设置 | `stores/app.settings` + 后端设置 | 主题切换要立刻生效 |
| 引擎状态 | `stores/app.engines`（复数） | 页头连接灯与设置页共用 |
| 引擎健康快照 | `OverviewView` 本地 `health` | 只有概览页用，不进全局 store |
| 已收尾的轮次 id | `stores/chat.lastFinishedRunId` | 只为一件事：丢掉收尾之后才到的权威快照，不把已并进历史的回复再接一遍 |
| 应用清单与安装进度 | `stores/app.apps` + `appProgress` | 应用页、设置页引擎卡、缺引擎横幅三处共用 |
| 提问卡片 | `stores/chat.asks` | 队列语义：一次只显示一张，答完弹下一张 |

**为什么历史由后端投影**：块顺序、工具结果按 `toolCallId` 配对，这两条规则只该有一份实现。
前端再写一遍必然漂移，而漂移的表现是「刷新之后消息顺序变了」。

## 应用骨架

```
┌──────────────────────────────────────────────────────────────────┐
│ 标题栏 44px   ▢ OhMyPiDesktop / 当前位置      ● 已连接/2 引擎  □ ✕ │
├────┬──────────────┬──────────────────────────────────────────────┤
│ 一 │  二级栏       │  页头 52px（标题 · 读数 · 动作）              │
│ 级 │  188px        │──────────────────────────────────────────────│
│ 导 │  （可选）      │  内容区                                       │
│ 航 │               │                                              │
│ 60 │               │                                              │
│ px │               │  输入区（对话页）                             │
└────┴──────────────┴──────────────────────────────────────────────┘
```

| 层 | 内容 | 规则 |
|---|---|---|
| 标题栏 | 品牌瓦片 · 当前位置 · **引擎连接灯（每个引擎一个）** · 窗控 | 只回答「我在哪、连上没有」，不放导航 |
| 一级 rail（60px） | 概览 / 对话 / 工作区 / 会话 / 模型 / 技能 / 插件 / MCP / 用量，图标 + 一行短标签竖排；底部是应用与设置 | 一级导航只有这一处；应用与设置都是低频入口，放底部 |
| 二级栏（188px，可选） | 会话列表 / 模型分组 / 技能分类 | 只有 rail 已在左侧占位，二级栏再宽就是两根侧栏 |
| 页头 | 标题 + 副标题 + 右侧动作 | 每个主区都有，位置固定 |
| 内容区 | 消息列 / 卡片 / 表格 | 底色走表面阶梯 |

**为什么一级导航放左 rail**：顶栏横向空间随窗口变化，图标入口在窄屏下最先被挤压；
竖排在左栏边缘，宽度恒定、位置恒定。设置放进 rail 底部而不是顶栏角落的纯图标——
入口靠猜等于没有入口。

**rail 选中态 = 淡底 + 左缘 2px 主色竖条 + 主色图标与文字**；会话行、技能行复用同一语言。

### 输入区是这一条消息的全部参数

一条消息的参数都在输入框里：它在哪个目录执行、发给哪个引擎、用哪个模型、
想多深、还剩多少上下文。页头只回答「现在是哪条对话」。

底栏是**两行**，不换行：

| 行 | 内容 |
|---|---|
| 参数行 | 工作目录 · 引擎 · 模型 · 思考档 ｜ 上下文水位 |
| 动作行 | 新建 · 附件 · 自动压缩 ｜ 排队 · 停止 · 发送 |

**为什么拆成两行**：一行自适应换行时，窗口稍窄就把水位挤到下一行、
把发送按钮推到中间，位置每天都不一样。两行之后左对齐的一列恒在左边、
动作恒在右边，用户不需要每次重新找按钮。

| 控件 | 行为 | 引擎差异 |
|---|---|---|
| **工作目录** | 展开面板：完整路径 + 最近用过的目录 + 「选择工作目录」 | — |
| **引擎** | 切 `omp` / `pi`。只列探测到的引擎；只有一个时不显示 | — |
| **模型** | 展开厂商 + 模型两级面板，带过滤框，请求 `set_model` | 共有 |
| **思考档** | `off` / `low` / `medium` / `high` …，请求 `set_thinking_level` | 共有 |
| **上下文水位** | 只读读数：细进度条 + 已用 / 窗口。超过 75% 转警告色 | 共有 |
| 停止 | 请求 `abort`，按下时 loading 锁尺寸 | 共有 |

**模型为什么是两级**：一份清单动辄几十个（OpenAI、Anthropic、Google 各一串），
一维下拉要滚很久才找到自己那一个。先选厂商再选模型，两屏各十几个。
**再给一个过滤框**：厂商内部也可能有二十几个，而用户多半记得名字里的一段
（`glm`、`4.1`），输两个字符就缩到两三条。

**模型面板要夹回视口内**：芯片在底栏中部而面板有 440px 宽，800px 窗口下
默认从芯片左缘往右长会直接溢出屏幕右边。打开时算一次水平偏移，够了。

**模型为什么有缓存**：引擎的 `get_available_models` 是运行时状态，
拿到它必须先拉起一个引擎进程（omp 冷启动实测 11 秒，pi 起一次 Node 3 秒）。
后端按引擎分桶缓存这份清单（TTL 30 秒），并且在「保存 / 删除服务商、
登录成功、重新探测引擎」之后主动失效。开下拉不必等进程冷启动。

**切引擎会做什么**：不切工作目录，不切会话。切换后：
若当前会话属于另一个引擎（会话文件路径不同），**新开一轮会话**并在消息流里插一条
分隔提示「已切到 omp，上面是 pi 的记录」。**不试图把历史搬过去**——两个引擎的会话文件
不是能互换的东西。

**已经读到的那段对话不能消失**：切引擎时先把它并进历史并插分隔，
后台拿到新引擎状态之后**把它拼回列表最前面**，而不是整列替换。
后者会让用户点一下引擎就把整段对话弄丢。会话列表也按引擎分桶缓存，
切过去先把目标引擎的列表摆上，不等一次往返。

**正在回答时不能切引擎**：这一轮的回答会落到原引擎的会话里，
而界面已经切到了另一个——两者的上下文就错位了。点下去给一句提示，而不是把按钮做成灰的。

**引擎不可用时的样子**：选择器只显示已探测到的；全都没有时输入框禁用，
上面一段横幅：「没找到引擎」+ 一行可复制的安装命令 + 「重新检测」+ 「去应用页安装」。
两条路都给：命令原文解决「我知道该跑什么」，应用页解决「我不想开终端」。

### 消息流

一条消息 = **角色徽章 + 内容**。两侧用不同的对齐与底色，方向一眼可辨：

- 徽章：全大写极小字，不画胶囊；用户侧染主色，助手侧中性
- **用户那侧是右对齐气泡**（宽度上限 78%，`brand-soft` 底 + 单角小圆角），
  **助手那侧是左对齐正文**，不套描边卡片。两边形状不同，长会话里不用靠徽章去找
  「哪段是我说的」；而助手侧不套卡片是因为一屏十几个相同圆角矩形会把“哪里是新的”抹平
- **一个回合只有一块正文**：思考段、正文与工具卡全部按引擎吐出的原始顺序排。
  不按字段类型分组——分组会把一轮里所有工具卡顶到正文前面，顺序一丢就读不出先干了什么
- **一次回答 = 一轮**：引擎会把一次回答拆成「工具调用前一条、工具调用后一条」多条助手
  消息，每条各带一份用量。后端投影把它们并成一轮——不并的话界面上一次回答会出两次
  助手徽章、两行读数，而直播那一轮也会因为块结构对不上历史而被重复渲染一遍
- 同角色连续的多轮只出徽章一次，且与上一条之间的间距取消

### 工具卡

严格一行：状态点 / 工具名 / 摘要 / 增删 / 耗时 / 箭头。默认收起，差异到货时自动展开。
除摘要以外每一段都是 `flex: none` —— 写错这一条的后果很具体：长工具名
（`powershell`）会被挤成一字一行竖排。

**不套描边盒子**：一轮回答里可能有十几个工具调用，每个一个带框的盒子就是十几个框，
读起来像一堆卡片而不是一串操作记录。运行中与出错只加一条左缘色。

展开后依次是**差异 → 参数 → 输出**：

| 段 | 什么时候有 | 内容 |
|---|---|---|
| 差异 | 只有改文件的工具有 | 逐行表格：旧行号 / 新行号 / 正文，增删染色 |
| 参数 | 工具收参数时有 | JSON 原文 |
| 输出 | 工具产出正文时 | 纯文本 |

**为什么差异排在输出前面**：改文件工具的输出是一句人话
（"Successfully replaced 1 block(s)"），真正要看的是改了哪几行。
差异行的渲染在 `DiffRows` 里，与工作区的差异视图共用同一份。

**工具卡不单独成行**：历史投影把工具块并进它所属的那一轮，
所以「调用工具 → 拿到结果 → 接着说」在界面上是一段连续的内容，而不是三条并列的卡。
- 引擎不支持的能力（如 pi 的 todo / goal）**不渲染占位**，直接不出现

差异到货时卡片自动展开——用户最想看的就是「它改了什么」，
而这一步如果由他们自己点，会漏掉。

差异段右侧有 **[看工作区]** 入口：打开右侧抽屉，显示这个文件**现在**在工作区里的
真实差异。引擎给的是它当时的改动，而用户可能又改过了、也可能已经提交了；
两者对不上的时候，真实差异才是用户要的。

抽屉而不是就地展开：就地展开会把消息列的排版撑开，
而用户想看差异时往往已经滚到了别处。

### 子代理面板（仅 omp）

右栏，宽度 260px，可折叠。三块：

1. **roster**：每行 `状态灯 · agent 名 · 描述`，右侧 `index`。
   状态灯四色：`pending` 灰 / `running` 呼吸主色 / `completed` 绿 / `failed｜aborted` 红。
2. **详情**（点选后）：进度条（`completionPercent`）、`stage` 一行、当前工具、
   `cost` / `tokens` / 上下文水位（`contextTokens / contextWindow`）、耗时。
3. **对话**：字节游标增量渲染，流式期只渲尾部 4000 字。
   底部两个动作：**[插话]**（`steer_subagent`，不打断父轮次）、**[取消]**（`cancel_subagent`）。

**pi 下整块不渲染**，也不留空栏。依据 `caps.subagents`。

## 工作区页

三栏：文件树 / 改动与历史 / 差异。三栏之上是一条**版本栏**。

### 版本栏

当前分支 / 上游 / 领先落后 / 取回 / 拉取 / 推送 / 强制推送。

它放在三栏之上，因为「在哪个分支」决定了下面每一栏的语境——
分支名散在页头、散在分支清单里，用户要扫两处才知道自己在哪。

**没有远端时不同渲染同步按钮**，而是换成一个「添加远端」的按钮 + 一句说明。
能力缺失不渲染（`AGENTS.md §7`）：同步类按钮在无远端时根本不出现，
但用户需要一个出口去把远端配起来。

**每个同步动作成功也要说话**：拉取这类动作没有可见副作用——
「拉完了但没有新提交」与「压根没点中」在界面上长得一模一样，
所以结果分两句：`已拉取 main：取回 N 个提交` / `已与远端同步（main 没有新提交）`。

**强制推送单独一个入口，且要二次确认**：它会覆盖别人的提交，
不能是普通推送的「高级选项」。确认面板里摆出那行命令原文，
选「无条件强制推送」时还要输入分支名且完全一致。分三档：

| 档 | 行为 |
|---|---|
| 普通 | 远端有本地没有的提交时被拒 |
| 带租约 | 只覆盖自己推过的历史；远端有你没见过的提交时拒绝 |
| 无条件 | 静默覆盖别人的提交；必须输入分支名确认 |

### 改动与历史

改动标签与历史标签是两个视角：

| 标签 | 回答 | 交互 |
|---|---|---|
| 改动 | 现在哪些文件变了 | 勾选分组、暂存/取出、丢弃、写提交信息并提交、分支清单与切换、合并、删除分支 |
| 历史 | 以前改过什么 | 点一行展开：提交正文 + 改动文件清单 + 逐行差异；点文件名只看它那一份 |

**列表不逐条画框线**：40 条提交就是 40 个框，读起来像一堆卡片。
整列靠留白分组，相邻两条之间一条极淡分隔，悬停才给底色；
展开的那一条给淡强调底 + 左缘主色竖条（竖条而不是整圈描边——描边会把
这一行框成盒子，列表就散了）。
提交详情也不再套第二层底与描边：它下面已经有一份自带圆角描边的差异视图，
再套上去就是三层框叠着表达同一件事。

**分支行的合并 / 删除只在悬停时出现**，因为一列分支每行都挂两个按钮
就是一片按钮墙，而这两个动作的频率远低于「切分支」。

**历史里每个提交都能展开。** 展开后先给整份提交的差异，点其中任何一个文件就换成
那个文件的差异——几千行一起渲染会卡，而用户通常只想看当前选中的那个。

**每个改动文件行有「历史」入口**：同一个文件改过几次、每次为什么改，
是决定「这次改动能不能收」的关键上下文。它把历史标签切到「只看这个文件」，
顶部一条过滤条可以退回全部提交。

```
┌ 文件树 220px ──┬ 改动 / 提交 ──────┬ 差异 ─────────────┐
│ ‹ OhMyPiDesktop│ 改动 17 │ 历史     │ .gitignore  +3656 │
│  assets        │ 工作区 17  全部加入 │ 1 # 构建产物      │
│  backend       │ ? .gitignore 加入 丢弃│ 2 build/bin/     │
│  docs          │ ? AGENTS.md  …     │ …                 │
│  AGENTS.md  7k │ ┌───────────────┐  │                   │
│  README.md  6k │ │写一句提交信息  │  │                   │
│                │ └───────────────┘  │                   │
│                │ 分支  + 新建        │                   │
└────────────────┴────────────────────┴───────────────────┘
```

| 区 | 内容 | 规则 |
|---|---|---|
| 文件树 | 逐层面包屑 + 条目 | **只读**。写文件是助手的事，界面不该有第二个写入口；窄窗口可用页头按钮整栏收起 |
| 改动 | 已暂存 / 未暂存分组，组内按目录折叠 | 目录头带这一组的增删合计；行为动作默认收起、悬停才出现（`GitFileRows`） |
| 提交 | 多行输入 + 提交按钮 | 没暂存或没写信息时按钮禁用，不弹「请先…」 |
| 历史 | 提交列表（短 hash / 主题 / 作者 / 时间） | 点一行展开详情；再点收起 |
| 差异 | 旧/新行号 + 正文，add/del/hunk 三色 | 二进制文件只显示 `(binary)`，不渲染乱码 |

**差异视图支持两种摆法**（右上角切换）：内联（旧行号 / 新行号 / 正文）与并排
（旧行号 / 旧正文 / 新行号 / 新正文）。并排是**真配对**：一段连续的删除后面跟着
一段连续的新增时，第 i 条删除与第 i 条新增摆在同一行。只把列切成四段、行还按原样堆着，
读到的是「左边一片空、右边一片空」——那比内联更难读。行渲染在 `DiffRows`
里，对话里的工具卡与这里共用一份。

**四种「不能正常工作」都要说清原因**，不能只显示空表格：

| 状态 | 显示 |
|---|---|
| 没装 Git | `reason` 原文（「系统里找不到 git」）+ 提示装 Git |
| 不是仓库 | 「这个目录还不是 Git 仓库」+ **初始化仓库**按钮 |
| 合并 / 变基未完成 | 顶部横幅 + 「继续 / 中止」+「标记已解决」 |
| 没有改动 | 「工作区干净，没有改动」 |

## 会话页

左侧二级栏 = 会话列表（**只列当前引擎的**，按工作目录分组），右侧 = 选中会话的详情与投影。

为什么按引擎过滤：两个引擎的会话文件不是能互换接着聊的东西，混在一张表里
会让人以为点开就能继续。

详情显示：标题、cwd、创建/更新时间、模型切换点、思考档、累计用量、条目列表。
底部动作：继续聊（跳对话页并 `switch_session`）、改名、导出 HTML、删除。

**删除必须二次确认**，且确认框里写明「同时删除子代理记录与附件」。

## 模型页

三个区块：服务商卡片 / 可用模型表 / 登录区（登录区仅 omp）。

**服务商卡片**：一张卡一条。卡上是它落盘的事实——
首字母方块 + 服务商名 + 主机名 + 引擎标签（两个引擎的配置完全独立，同名可以各有一份）、
协议、密钥有没有（只有「有没有」，不显示原值）、前六个模型 id（多了给一个可点的 `+N`，
点开摊平）。卡上四个动作：

| 动作 | 行为 |
|---|---|
| **测一下** | 向上游问一次模型清单，顺带验证地址、协议与密钥对不对 |
| **拉模型** | 问上游「有哪些模型」，把清单填进编辑框 |
| 编辑 | 打开编辑弹窗 |
| 删除 | 二次确认后删 |

「测一下」与「拉模型」走的是同一份后端能力（`upstream` 包）：
按协议向 `/models` 发一次 GET，把响应归一成模型 id 列表。
密钥不给就用已保存的那个——界面拿到的是掩码，原值只在后端的配置里。

「拉模型」填进编辑框而不是直接写配置：拉回来的只有 id，
上下文窗口与最大输出这些字段还得人填。直接写会把「刚拉下来的清单」
当成「用户确认过的配置」。

**模型表**：provider / model id / 上下文窗口 / 是否推理模型 / 输入模态。
只读——改模型去服务商那节。

**登录区（omp）**：可登录服务商列表 + 登录态。点「登录」发起 OAuth，
界面显示 `open_url` 给的链接（**优先给可复制的 `launchUrl`**，因为默认浏览器可能打不开）。
pi 下这块替换成一行提示：「pi 的登录在终端里做：`pi auth`」。

引擎会报回八九十条可登录服务商。**默认只列 6 条**（已登录的全留）
加一个可点的「展开全部」与过滤框——全铺出来会把下面的模型表推到几屏之外，
而这一节最常见的用途是「我登过谁」。

## 技能页

一行一技能：名称 / 来源（用户 / 工作区 / 插件 / 内置）/ 描述 / 开关 / 操作。

- 开关直接写 `SKILL.md` 的 `enabled`，失败要回滚开关位置并给原文
- 点开抽屉显示原文（只读 + 「在编辑器里打开」）
- **只有用户目录下的技能**能改和删。工作区与插件来的技能：开关灰掉，悬停说明原因
- pi 的发现规则不同，但界面同构；来源标签按引擎各自填充

## 插件页

一行一插件：名称 / 版本 / 来源 / 操作（卸载）。

顶部一个安装输入框 + 「安装」按钮。**安装是长任务**：按钮进 loading 并锁尺寸，
下方显示阶段日志（逐行追加、可滚动、可复制），完成后刷新列表。

pi 下改叫「扩展」：只列 `settings.json` 里的扩展源，安装/卸载调 `pi install/remove`。

## 用量页

四个 KPI 卡 + 一张趋势图 + 两张分布（按模型 / 按会话）。

- 数据源：会话文件的 `message.usage` 累加。**不建用量表**
- 分桶：`24h` / `今天` / `7天` / `14天` / `30天`，缺桶补 0（否则趋势图会断）
- 天粒度从**本地零点**起算（跨天会话不能整体落在一天里）
- 色值取 `--omp-ch-*`，不写死

pi 下可用（会话文件里也有 usage），但**没有** `usageLimit` 那类账号配额信息。

## 应用页

两段：**已安装** / **未安装**。每段标题带数量，空的那段不渲染。

一行一个引擎（只两个，不做表格）：

```
┌ [omp]  omp/18.13.2  → 18.14.0 [有新版本]        [重新安装] [升级]  ┐
│ 安装渠道  omp 官方安装器                                          │
│ 可执行文件 C:\Users\me\AppData\Local\omp\omp.exe                   │
│ ▸ 正在执行   命令与日志（可展开）                                  │
│ 官方文档                                                          │
└──────────────────────────────────────────────────────────────────┘
```

| 区 | 内容 | 规则 |
|---|---|---|
| 版本 | 本地版本，落后时给 `→ 最新版` 与「有新版本」标签 | 上游查不到时显示「最新版未知」，**不说「已是最新」** |
| 动作 | 重新安装 / 升级 / 卸载 | 三个都是五态按钮；加载态锁尺寸 |
| 事实 | 安装渠道 + 可执行文件路径 | 未安装时换成**一行可复制的安装命令** |
| 进度 | 命令原文 + 阶段 + 逐行日志 | 默认收起；只在跑过或有现场时出现，不预留空位 |

**为什么不给灰按钮**：按钮该不该存在由后端算好（`can_install` / `can_update` /
`can_uninstall`）。判不出来就不渲染，并给一句 `blocker`——装着一个应用却没有
卸载按钮，用户只会以为漏了。

**为什么进度默认收起**：装一个引擎的日志能到几百行，常驻展开会把「装的什么版本」
挤到看不见的地方。

**三条命令都是原文可复制**：命令是从引擎官方文档原样抄来的，与真正执行的是同一串。
所以用户可以拿它到别的机器上跑。分发事实见 [modules/apps.md](modules/apps.md)。

## 设置页

六个分节，每节一张卡：

| 节 | 内容 |
|---|---|
| 外观 | 主题（浅/深）、字号缩放、减少动效 |
| 启动行为 | 开机自启、启动时回到上次会话、上次那个会话是哪条、数据目录（可一键打开） |
| 引擎 | **每个引擎一张卡**：探测结果、版本、来源、渠道、显式路径、落盘布局（点路径即定位）、重启。缺引擎时给安装命令原文 + 「去应用页安装」 |
| 工作区 | 当前目录 + **最近用过的目录**（一行一个：点行即切，`×` 只从记忆里去掉）+ 切换按钮 |
| 引擎配置 | 配置文件清单（文件名标签）+ 只读原文（CodeMirror，按扩展名给 yaml / json 高亮）；文件不存在时显示「还没生成过」 |
| 关于 | 版本、契约版本、日志抽屉 |

探测结果的三种呈现：`已找到 omp 18.13.1` / `没找到 pi`（+ 安装命令 + 去应用页）/ `路径无效`（+ 重新选择）。

**这里不装引擎。** 装 / 升级 / 卸载统一在「应用」页：两处各放一个安装按钮，
必然会出现一个说装了、一个说没装。

**开机自启的开关状态以注册表为准**：用户在任务管理器里禁掉之后，
这里该显示「关」。开关发一次请求，成功后才写镜象值；失败时开关自己拨回去。

**配置原文只读不写**。写引擎配置有节点级接口（它们只改自己掌管的那几个键）；
原文编辑会让它们下一次写入把用户手改的东西一起覆盖掉，而那种丢失不会报错。

## 跨页共同规则

- 每个异步动作都有五态（默认 / 悬停 / 按下 / 禁用 / 加载），加载态锁尺寸
- 每个失败都给**原因原文**，不让消息无声消失
- 空状态必须说「为什么空」和「怎么让它不空」，不写「暂无数据」
- 引擎不支持的功能：**不渲染**，不渲染成灰掉的按钮（灰按钮会被当成「我还没权限」）
- **错误必须写成一句话，不是只把面板染红**：对话页的错误条带原话与关闭按钮
- 对话内的过程提示（已排队 / 已切引擎）浮在输入区上方 4 秒，不打扰消息流；
  全局动作结果（保存成功 / 装插件失败）才用右下角 toast

## 输入区

三件事都在输入框里完成，因为它们都属于「这次要发什么」：

| 入口 | 触发 | 结果 |
|---|---|---|
| `/` 命令 | 行首输入 `/` | 弹出命令表：**内置**（新建 / 换模型 / 思考档 / 压缩 / 复制 / 导出 / 刷新）与**引擎命令**（扩展 / 提示模板 / 技能）合成一张表，内置条目带「内置」标记 |
| `@` 引用 | 输入 `@` | 弹出工作区文件浏览器，逐级下钻；选中的文件变成一条附件 |
| 粘贴图片 | `Ctrl+V` | 截图直接进附件条，带缩略图 |
| 选择文件 | 回形针按钮 | 系统文件选择框；工作区内的存相对路径，工作区外的存绝对路径 |

**附件分两类，走两条完全不同的路**（这是唯一需要记住的差别）：

- **文件引用只拼路径清单进正文**。引擎用它自己的读文件工具去看，
  上下文按需增长。我们不把文件内容内联进 prompt：那会让同一份内容记两遍账，
  而且「引擎看过什么」变得没法追溯。
- **图片必须走 prompt 的 `images` 字段**。这是协议里唯一能传二进制的通道；
  base64 塞进正文只是一段文字，模型看不见，还会瞬间吃掉几万 token。

上限：单次最多 8 张图、40 个文件，单张图 4MB。超限在发出去之前就拦下并说清原因。

**模型不收图时**：回形针与粘贴会提前拒绝并说明「当前模型不收图片」，
提示用户换模型。判据是模型 `input` 里有没有 `image`；引擎没报这个字段时不拦
（读不到状态不等于不支持）。

**草稿按会话保存**：切走再切回来还在，关掉窗口也不丢。
没有会话（新建态）时存在一个固定键下。最多保留 20 条，超出淘汰最旧的。
