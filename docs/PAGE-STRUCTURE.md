# 页面结构

八个路由。每个页面回答一个真问题，没有「总览台」这类自造页。

| 路由 | 页面 | 回答的问题 | 引擎差异 |
|---|---|---|---|
| `/chat` | 对话 | 它在干什么，我下一步说什么 | 子代理面板仅 omp |
| `/workspace` | 工作区 | 它到底改了什么，我能不能收成一次提交 | 无 |
| `/sessions` | 会话 | 我以前聊过什么，哪些能接着聊 | 列表按当前引擎过滤 |
| `/models` | 模型 | 现在能用哪些模型，密钥配了没 | 登录向导仅 omp |
| `/skills` | 技能 | 我有哪些技能，哪些开着 | 发现规则不同，UI 同构 |
| `/plugins` | 插件 | 我装了哪些扩展 | pi 只有「扩展源」列表 |
| `/usage` | 用量 | 花了多少 token，花在哪 | pi 只有会话内用量 |
| `/settings` | 设置 | 外观、引擎路径、工作目录、关于 | 引擎路径按引擎分开 |

## 状态归属

| 状态 | 住哪 | 理由 |
|---|---|---|
| 当前轮（流式块） | `stores/chat.turn` | 高频变化，只在这一处 |
| 历史轮 | `stores/chat.history` | 由后端投影，前端不再算 |
| 引擎选择（omp/pi） | `stores/app.engineKind` + 后端设置 | 输入框与多个页面共用 |
| 子代理 roster | `stores/agents.roster` | 仅 omp；随会话切换清空 |
| 会话列表 | `stores/app.sessions` | 跨页共用 |
| 设置 | `stores/app.settings` + 后端设置 | 主题切换要立刻生效 |
| 引擎状态 | `stores/app.engines`（复数） | 页头连接灯与设置页共用 |
| 提问卡片 | `stores/chat.asks` | 队列语义：一次只显示一张，答完弹下一张 |

**为什么历史由后端投影**：块顺序、工具结果按 `toolCallId` 配对，这两条规则只该有一份实现。
前端再写一遍必然漂移，而漂移的表现是「刷新之后消息顺序变了」。

## 应用骨架

```
┌──────────────────────────────────────────────────────────────────┐
│ 标题栏 44px   ▢ OhMyPiDesktop / 当前位置      ● 已连接/2 引擎  □ ✕ │
├────┬──────────────┬──────────────────────────────────────────────┤
│ 一 │  二级栏       │  页头 52px（标题 · 读数 · 动作）              │
│ 级 │  188px        │──────────────────────────────────────────────│
│ 导 │  （可选）      │  内容区                                       │
│ 航 │               │                                              │
│ 60 │               │                                              │
│ px │               │  输入区（对话页）                             │
└────┴──────────────┴──────────────────────────────────────────────┘
```

| 层 | 内容 | 规则 |
|---|---|---|
| 标题栏 | 品牌瓦片 · 当前位置 · **引擎连接灯（每个引擎一个）** · 窗控 | 只回答「我在哪、连上没有」，不放导航 |
| 一级 rail（60px） | 对话 / 工作区 / 会话 / 模型 / 技能 / 插件 / 用量，图标 + 一行短标签竖排 | 一级导航只有这一处；设置是 rail 底部的一等入口 |
| 二级栏（188px，可选） | 会话列表 / 模型分组 / 技能分类 | 只有 rail 已在左侧占位，二级栏再宽就是两根侧栏 |
| 页头 | 标题 + 副标题 + 右侧动作 | 每个主区都有，位置固定 |
| 内容区 | 消息列 / 卡片 / 表格 | 底色走表面阶梯 |

**为什么一级导航放左 rail**：顶栏横向空间随窗口变化，图标入口在窄屏下最先被挤压；
竖排在左栏边缘，宽度恒定、位置恒定。设置放进 rail 底部而不是顶栏角落的纯图标——
入口靠猜等于没有入口。

**rail 选中态 = 淡底 + 左缘 2px 主色竖条 + 主色图标与文字**；会话行、技能行复用同一语言。

```
┌───────────────────────────────────────┬──────────────────┐
│ 消息列                                 │ 子代理面板（仅 omp）│
│  ┌ 用户徽章 ────────────────────────┐  │ ┌ roster ──────┐ │
│  │ 用户消息                          │  │ │ ● scout  运行 │ │
│  └──────────────────────────────────┘  │ │ ✓ reviewer    │ │
│  ┌ 助手徽章 ────────────────────────┐  │ └──────────────┘ │
│  │▎思考块（可折叠，流式只渲尾部）      │  │ ┌ 选中详情 ────┐ │
│  │▎正文                             │  │ │ 进度 / 成本   │ │
│  │▎工具卡（参数/输出/耗时）           │  │ │ 对话（游标）  │ │
│  │▎提问卡（confirm/select/…）        │  │ │ [插话] [取消]│ │
│  └──────────────────────────────────┘  │ └──────────────┘ │
├───────────────────────────────────────┴──────────────────┤
│ [引擎 ▾omp] [模型 ▾] [思考档 ▾]                  [停止]    │
│ ┌──────────────────────────────────────────────────────┐ │
│ │ 输入框（多行，Enter 发送 / Shift+Enter 换行）           │ │
│ └──────────────────────────────────────────────────────┘ │
│ 排队：3 条 · 上下文 42% · 1.2k tok/s                     │
└──────────────────────────────────────────────────────────┘
```

### 输入区是引擎的唯一入口

输入框上方一行控件，从左到右：

| 控件 | 行为 | 引擎差异 |
|---|---|---|
| **引擎选择** | 切 `omp` / `pi`。只列探测到的引擎；只有一个时不显示 | — |
| 模型选择 | 展开搜索列表，请求 `set_model` | 共有 |
| 思考档 | `off` / `low` / `medium` / `high` …，请求 `set_thinking_level` | 共有 |
| 停止 | 请求 `abort`，按下时 loading 锁尺寸 | 共有 |
| 队列 chip | 显示排队条数，点开可移除 / 提前发送 | 移除/提前**仅 omp** |

**切引擎会做什么**：不切工作目录，不切会话。切换后：
若当前会话属于另一个引擎（会话文件路径不同），**新开一轮会话**并在消息流里插一条
分隔提示「已切到 omp，上面是 pi 的记录」。**不试图把历史搬过去**——两个引擎的会话文件
不是能互换的东西。

**引擎不可用时的样子**：选择器只显示已探测到的；全都没有时输入框禁用，
上面一段横幅：「没找到 omp。装好后点这里重新检测。」+ 一行可复制的安装命令 + 「重新检测」按钮。

### 消息流

一条消息 = **角色徽章 + 内容容器**，用户与助手同一语言，不做「右气泡 / 左头像」的分裂：

- 徽章：全大写极小字 + 胶囊描边；用户侧染淡靛，助手侧保持中性
- 助手正文是一块独立面板（`raised` 底 + 1px 描边 + **左侧 2px 脊线**），脊线是「助手列」的身份线
- **一个回合只有一个徽章、一个内容面板**：思考段、正文与工具卡全部内联在同一块面板里，
  按引擎吐出的原始顺序排。不按字段类型分组——分组会把一轮里所有工具卡顶到正文前面，
  顺序一丢就读不出先干了什么
- 引擎不支持的能力（如 pi 的 todo / goal）**不渲染占位**，直接不出现

### 子代理面板（仅 omp）

右栏，宽度 260px，可折叠。三块：

1. **roster**：每行 `状态灯 · agent 名 · 描述`，右侧 `index`。
   状态灯四色：`pending` 灰 / `running` 呼吸主色 / `completed` 绿 / `failed｜aborted` 红。
2. **详情**（点选后）：进度条（`completionPercent`）、`stage` 一行、当前工具、
   `cost` / `tokens` / 上下文水位（`contextTokens / contextWindow`）、耗时。
3. **对话**：字节游标增量渲染，流式期只渲尾部 4000 字。
   底部两个动作：**[插话]**（`steer_subagent`，不打断父轮次）、**[取消]**（`cancel_subagent`）。

**pi 下整块不渲染**，也不留空栏。依据 `caps.subagents`。

## 工作区页

三栏，回答「它改了什么」：

```
┌ 文件树 220px ──┬ 改动 / 提交 ──────┬ 差异 ─────────────┐
│ ‹ OhMyPiDesktop│ 改动 17 │ 历史     │ .gitignore  +3656 │
│  assets        │ 工作区 17  全部加入 │ 1 # 构建产物      │
│  backend       │ ? .gitignore 加入 丢弃│ 2 build/bin/     │
│  docs          │ ? AGENTS.md  …     │ …                 │
│  AGENTS.md  7k │ ┌───────────────┐  │                   │
│  README.md  6k │ │写一句提交信息  │  │                   │
│                │ └───────────────┘  │                   │
│                │ 分支  + 新建        │                   │
└────────────────┴────────────────────┴───────────────────┘
```

| 区 | 内容 | 规则 |
|---|---|---|
| 文件树 | 逐层面包屑 + 条目 | **只读**。写文件是助手的事，界面不该有第二个写入口 |
| 改动 | 已暂存 / 未暂存分组，`status` 首字母染色 | 点一行看它的差异；「加入 / 取出 / 丢弃」都带 loading |
| 提交 | 多行输入 + 提交按钮 | 没暂存或没写信息时按钮禁用，不弹「请先…」 |
| 历史 | 提交列表（短 hash / 主题 / 作者 / 增删） | 只读 |
| 分支 | 当前分支高亮，点其它分支即切换 | 切换是写操作，带 loading |
| 差异 | 旧/新行号 + 正文，add/del/hunk 三色 | 二进制文件只显示 `(binary)`，不渲染乱码 |

**四种「不能正常工作」都要说清原因**，不能只显示空表格：

| 状态 | 显示 |
|---|---|
| 没装 Git | `reason` 原文（「系统里找不到 git」）+ 提示装 Git |
| 不是仓库 | 「这个目录还不是 Git 仓库」+ **初始化仓库**按钮 |
| 合并 / 变基未完成 | 顶部横幅 + 「继续 / 中止」+「标记已解决」 |
| 没有改动 | 「工作区干净，没有改动」 |

## 会话页

左侧二级栏 = 会话列表（**只列当前引擎的**，按工作目录分组），右侧 = 选中会话的详情与投影。

为什么按引擎过滤：两个引擎的会话文件不是能互换接着聊的东西，混在一张表里
会让人以为点开就能继续。

详情显示：标题、cwd、创建/更新时间、模型切换点、思考档、累计用量、条目列表。
底部动作：继续聊（跳对话页并 `switch_session`）、改名、导出 HTML、删除。

**删除必须二次确认**，且确认框里写明「同时删除子代理记录与附件」。

## 模型页

两张表 + 一个登录区（登录区仅 omp）。

**服务商表**：名称 / 类型 / 密钥状态（`已配` / `未配` + 末尾 4 位）/ 模型数 / 操作。
密钥输入框默认显示 `••••••••`，用户不动就不覆盖已存密钥。

**模型表**：provider / model id / 上下文窗口 / 是否推理模型 / 成本档。
点一行可设为当前模型。

**登录区（omp）**：可登录服务商列表 + 登录态。点「登录」发起 OAuth，
界面显示 `open_url` 给的链接（**优先给可复制的 `launchUrl`**，因为默认浏览器可能打不开）。
pi 下这块替换成一行提示：「pi 的登录在终端里做：`pi auth`」。

## 技能页

一行一技能：名称 / 来源（用户 / 工作区 / 插件 / 内置）/ 描述 / 开关 / 操作。

- 开关直接写 `SKILL.md` 的 `enabled`，失败要回滚开关位置并给原文
- 点开抽屉显示原文（只读 + 「在编辑器里打开」）
- **只有用户目录下的技能**能改和删。工作区与插件来的技能：开关灰掉，悬停说明原因
- pi 的发现规则不同，但界面同构；来源标签按引擎各自填充

## 插件页

一行一插件：名称 / 版本 / 来源 / 操作（卸载）。

顶部一个安装输入框 + 「安装」按钮。**安装是长任务**：按钮进 loading 并锁尺寸，
下方显示阶段日志（逐行追加、可滚动、可复制），完成后刷新列表。

pi 下改叫「扩展」：只列 `settings.json` 里的扩展源，安装/卸载调 `pi install/remove`。

## 用量页

四个 KPI 卡 + 一张趋势图 + 两张分布（按模型 / 按会话）。

- 数据源：会话文件的 `message.usage` 累加。**不建用量表**
- 分桶：`24h` / `今天` / `7天` / `14天` / `30天`，缺桶补 0（否则趋势图会断）
- 天粒度从**本地零点**起算（跨天会话不能整体落在一天里）
- 色值取 `--omp-ch-*`，不写死

pi 下可用（会话文件里也有 usage），但**没有** `usageLimit` 那类账号配额信息。

## 设置页

四个分节，每节一张卡：

| 节 | 内容 |
|---|---|
| 外观 | 主题（浅/深/跟随系统）、字号缩放、减少动效 |
| 引擎 | **每个引擎一张卡**：探测结果、版本、来源、显式路径、落盘布局（点路径即定位）、重启。缺引擎时给安装命令原文 |
| 工作区 | 当前目录 + **最近用过的目录**（一行一个：点行即切，`×` 只从记忆里去掉）+ 切换按钮 |
| 关于 | 版本、契约版本、日志抽屉、数据目录「打开所在位置」 |

**没有「安装」按钮。** 引擎由用户自己装；我们只探测。
探测结果的三种呈现：`已找到 omp 18.13.1` / `没找到 pi`（+ 安装命令）/ `路径无效`（+ 重新选择）。

## 跨页共同规则

- 每个异步动作都有五态（默认 / 悬停 / 按下 / 禁用 / 加载），加载态锁尺寸
- 每个失败都给**原因原文**，不让消息无声消失
- 空状态必须说「为什么空」和「怎么让它不空」，不写「暂无数据」
- 引擎不支持的功能：**不渲染**，不渲染成灰掉的按钮（灰按钮会被当成「我还没权限」）
